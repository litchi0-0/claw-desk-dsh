# 移动动画与窗口位移同步

## 问题与实施计划

用户指出角色在动画开头尚未迈步，窗口却已快速移动。核查原版 1.4.0 `roam.js`，位移使用 `t * (2 - t)`，初速度最大、随后持续减速；时钟从请求动画时开始，没有等待图片显示回执。素材节奏与位移节奏恰好相反。

本次计划并完成：逐段查看四种移动/转身素材的时间采样，确定适合现有漫游的片段；实现可配置速度时间轴与加载回执同步；执行实际 roam.js 的模拟时钟回归；更新主题、本机应用、文档与 GitHub。

## 四段素材逐项对比

基于当前透明 WebP 实际帧采样，全部约 10.042 秒，原片采样率 24 FPS，未改素材或播放速度。以下边界是目视标定，精度约 1–3 帧，不是逐脚骨骼跟踪。

| 动画 | 观察到的节奏 | 本次适配 |
| --- | --- | --- |
| 螃蟹走路 | 开头正面站立，约 0.6 秒后开始转身/迈步；约 1.25–7.4 秒持续走；约 8 秒站回正面，余段为收尾 | 保持为默认自动漫游，窗口速度按下述时间轴推进 |
| 原地左转奔跑 | 先站立，约 1.3 秒转身，约 1.8–4.6 秒奔跑，随后有跌倒、趴地和起身 | 继续支持完整手动点播；不把整个片段当作连续平移，避免趴地时仍滑行 |
| 原地漂浮踏步 | 正面为主，约 0.75 秒后交替踏步与悬浮，末段恢复站立 | 保留点播；本次不自动替换侧向走路，后续若加入垂直漂浮需单独定义位移方向和节奏 |
| 小幅度原地360度旋转展示 | 约 1.5 秒开始原地转圈，约 5 秒后正面站立/表情收尾 | 原地展示，不绑定平移 |

## 当前走路时间轴（主题 1.4.1）

| 动画播放时间 | 窗口速度 |
| --- | --- |
| 0–625 ms | 原地准备，速度为 0 |
| 625–1250 ms | 逐渐加速，与转身/起步衔接 |
| 1250–7417 ms | 均匀移动 |
| 7417–8000 ms | 逐渐减速、收步 |
| 8000–10042 ms | 停住，播完正面站立收尾，再回普通待机 |

不是把整段视频快放或延长，而是对分段线性速度做积分，得到窗口位置。开头和收尾静止段不再滑行，中间不再一路减速。每轮强制从动画第一帧重播，并从 `committed` 显示回执开始计时；加载期间窗口不移动，失败、被替代或 10 秒无回执会取消本轮。

普通目标距离会按角色缩放限制：参考窗口高度 270 px，巡航上限 80 px/s；一段走路的有效积分约 6.77 秒，对应参考尺寸下约 542 px 的最大平移。短距离会降低整个速度曲线的幅度，仍保持相同时间节奏。围栏/屏幕外恢复保持原目标，不强行截短导致永远回不去；这种恢复可能超过普通速度上限。

拖拽、工作、权限气泡、手动点播、菜单或关闭漫游可以中断移动。自动待机动作正在播放时也会阻止已预约的漫游开始，避免轮候计时器在小动作播到一半时抢走画面。保留原有朝向修正、冻结窗口尺寸、命中窗口跟随、屏幕/围栏约束和高优先级状态恢复。未配置 `roamMotion` 的其他主题仍沿用原来的移动时间曲线。

## 配置与维护

`theme.json.roamMotion` 指定素材、整段时长、参考高度、巡航速度与 `keys: [[时间ms, 相对速度], ...]`。文件必须属于当前主题 `states.roam` 且时长匹配主题素材；非法配置回落原逻辑。`configure-dsh-auto-idle.py` 同时生成此默认配置，正常构建/更新主题不会丢失。

`scripts/patch-clawd-roam.py` 对原版源码做唯一匹配补丁。安装器还让状态请求转发显示回执，不改变真实工作状态。测试 fixture 来自 Clawd on Desk 1.4.0，保留 AGPL 许可。

## 验证边界

46 项 Node 测试通过，其中 8 项新增移动回归覆盖：准备段静止、中段匀速、收尾静止、完整时长、等待显示回执、回执失败/超时、取消后旧回执、手动点播/工作中断、普通距离上限、窗口尺寸固定，以及其他主题保留原行为。

已构建并核对安装补丁与签名；实际加载回执和位移时序通过原版 roam.js 的模拟时钟执行验证。没有修改源素材，也没有声称实现逐脚接地约束。真实多显示器/所有缩放比例及每个随机路径的观感仍需使用中观察。
